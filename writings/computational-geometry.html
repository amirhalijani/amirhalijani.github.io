Computational Geometry

An exploration of convex hulls, line segment intersections, and Voronoi diagrams — bridging continuous geometric intuition and discrete, provably efficient algorithms.

§1 Abstract

This paper explores computational geometry through several fundamental examples — including the computation of intersection points, convex hulls, and Voronoi diagrams. Each problem demonstrates how geometric objects that appear intuitive on paper demand deep algorithmic care to handle correctly and efficiently.

§2 History of Computational Geometry

Computational geometry emerged in the late 1970s from the design and analysis of algorithms. Over time it grew into an independent discipline with specialized journals, dedicated conferences, and a broad research community. Its applications span computer graphics, Geographic Information Systems (GIS), robotics, and many other fields.

§3 Planar Convex Hull Computation

Definition — Convex Set
A subset $S$ of the plane is called convex if and only if for every pair of points $p, q \in S$, the line segment $\overline{pq}$ lies entirely within $S$.

The convex hull $\text{CH}(S)$ is the smallest convex set containing $S$. More precisely, it is the intersection of all convex sets that contain $S$.

Figure 1 — A convex set (left) where segment $\overline{pq}$ stays inside, versus a non-convex set (right) where it exits.

Concretely: imagine several nails on a board. Stretching a rubber band around all of them and releasing it — the region it encloses is the convex hull.

Given a set of points $P = \{p_1, p_2, \ldots, p_n\}$ in the plane, we compute a list of points from $P$ that are vertices of $\text{CH}(P)$, ordered clockwise.

3.1 — A Simple but Inefficient Algorithm

The first approach is based directly on the geometric definition of a convex hull. In this method, known as Slow Convex Hull, for every pair of points $p, q$, we check whether all other points lie to the right of the directed line $\overrightarrow{pq}$. If so, segment $\overline{pq}$ is an edge of the convex hull.

Since this check is repeated for every pair, and each check inspects all remaining points:

$$T(n) = O(n^3)$$

This is impractical for real inputs. The method is also numerically fragile — floating-point errors can produce inconsistent or degenerate output.

Figure 2 — Slow Convex Hull tests every pair of points. Hull edges are shown dashed.

3.2 — Efficient Algorithm: Incremental Method

The standard approach builds the convex hull incrementally by constructing the upper hull and lower hull separately.

Points are first sorted lexicographically — by $x$-coordinate, breaking ties by $y$. The algorithm then scans twice: once for the upper hull, once for the lower hull.

The key invariant is: if three consecutive points do not form a right turn, the middle point is redundant and must be removed. This preserves convexity while discarding unnecessary points.

Concept — Right Turn vs. Left Turn

Given three consecutive points $A$, $B$, $C$, we determine the orientation of the path $A \to B \to C$ using the 2D cross product:

$$\text{cross} = (B_x - A_x)(C_y - B_y) - (B_y - A_y)(C_x - B_x)$$
  • $\text{cross} > 0$ → Left turn (counterclockwise)
  • $\text{cross} < 0$ → Right turn (clockwise)
  • $\text{cross} = 0$ → Collinear

In convex hull algorithms (e.g., Graham Scan, Monotone Chain), only right turns are kept. A left turn means the middle point creates an inward dent — it is removed.

Figure 3 — Incremental upper hull construction. Points failing the right-turn test are removed (marked ✕).
Complexity
With $O(n \log n)$ sorting and a linear scan for each hull, the incremental algorithm achieves:
$$T(n) = O(n \log n)$$
This is optimal for the comparison-based model, since sorting reduces to convex hull computation.

§4 Line Segment Intersection Points

Finding intersections among line segments plays a central role in geometric network analysis, cartography, power-line routing, topological structures, and many engineering domains. It is a simplified version of map-overlay in GIS systems, where roads, rivers, region boundaries, and other features must be intersected.

4.1 — Problem Definition

Given a set of closed line segments in the plane:

$$S = \{s_1, s_2, \ldots, s_n\}$$

Compute all intersection points together with the list of segments forming each intersection. Segments are closed so that an endpoint lying on another segment also counts as an intersection.

Figure 4 — Example of the Line Segment Intersection problem. Intersection points shown as white-filled circles.
Naïve Approach & Its Weakness
Checking every pair of segments runs in $O(n^2)$ time. In practice, the number of actual intersections is far smaller than $\binom{n}{2}$, so we need an output-sensitive algorithm whose cost scales with the actual intersection count.

4.2 — The Sweep Line Algorithm

The standard algorithm uses a horizontal sweep line $\ell$ moving top to bottom. Three event types are processed:

  • Segment start — $\ell$ reaches the upper endpoint of a segment.
  • Segment end — $\ell$ passes the lower endpoint.
  • Intersection event — two segments cross.

At each moment, segments currently crossing $\ell$ are stored in a status structure ordered by their $x$-coordinate at $\ell$'s current height.

Key Insight
If two segments intersect, then just before they cross, they must be horizontal neighbors in the status structure. Therefore, only adjacent pairs ever need to be tested.
  • On insertion — a new segment is tested against its two new neighbors.
  • On intersection — the two segments swap positions; each is tested against its new neighbor.
  • On deletion — the newly adjacent pair is tested against each other.
Figure 5 — Sweep line $\ell$ (orange dashed) moves top to bottom, processing events as it encounters segment endpoints and intersections.
Complexity
$$T(n, I) = O((n + I) \log n)$$ where $I$ is the number of intersections. This is output-sensitive and far superior to the naïve $O(n^2)$.

§5 Voronoi Diagram: Definition, Properties, and Computation

5.1 — Introduction

The Voronoi diagram is a fundamental geometric structure with applications in social geography, physics, astronomy, robotics, and more. It is based on the Voronoi assignment model: every point in the plane is assigned to its nearest site (seed point).

Economically, assuming transportation cost is proportional to Euclidean distance, consumers minimize cost by going to the nearest site. The Voronoi diagram partitions the plane into regions — one per site — containing all points closer to that site than to any other.

Figure 6 — A Voronoi diagram for 5 sites. Each colored region contains all points closer to its site than to any other.

5.2 — Definitions and Basic Properties

Definition 5.1 — Euclidean Distance
$$\text{dist}(p, q) = \sqrt{(p_x - q_x)^2 + (p_y - q_y)^2}$$
Definition 5.2 — Voronoi Diagram
Let $P = \{p_1, p_2, \ldots, p_n\}$ be a set of $n$ distinct points. The Voronoi diagram $\text{Vor}(P)$ partitions the plane into $n$ cells such that point $q$ belongs to the cell of site $p_i$ iff: $$\text{dist}(q, p_i) < \text{dist}(q, p_j) \quad \forall j \neq i$$ The cell of $p_i$ is denoted $V(p_i)$.
Definition 5.3 — Half-Plane
The perpendicular bisector of segment $p_i p_j$ divides the plane into two half-planes. We denote the open half-plane containing $p_i$ as: $$h(p_i, p_j) = \{ r \mid \text{dist}(r, p_i) < \text{dist}(r, p_j) \}$$
Observation 5.1
$$V(p_i) = \bigcap_{\substack{1 \le j \le n \\ j \neq i}} h(p_i, p_j)$$ So $V(p_i)$ is the intersection of $n-1$ half-planes — an open, convex (possibly unbounded) polygonal region with at most $n-1$ vertices and $n-1$ edges.
Theorem 5.1
If all sites are collinear, $\text{Vor}(P)$ consists of $n-1$ parallel lines. Otherwise, $\text{Vor}(P)$ is connected and all its edges are either line segments or rays (no full lines).
Theorem 5.2 — Size Bounds (for $n \geq 3$)
$$\text{vertices of } \text{Vor}(P) \leq 2n - 5, \qquad \text{edges} \leq 3n - 6$$ Proof sketch: Add a virtual vertex $v_\infty$ connecting all rays. The resulting planar graph satisfies Euler's formula $V - E + F = 2$, and since every vertex has degree $\geq 3$: $2E \geq 3V$. Solving these gives the bounds.
Definition 5.4 — Largest Empty Circle
The largest empty circle $C_P(q)$ centered at $q$ with respect to $P$ is the largest circle centered at $q$ containing no site in its interior.
Theorem 5.3 — Vertex and Edge Characterization
  • $q$ is a vertex of $\text{Vor}(P)$ $\iff$ at least three sites lie on the boundary of $C_P(q)$.
  • The bisector of $p_i$ and $p_j$ defines an edge of $\text{Vor}(P)$ $\iff$ there exists a point $q$ on the bisector such that $p_i$ and $p_j$ lie on the boundary of $C_P(q)$ with no other site inside.

5.3 — Computing the Voronoi Diagram: Fortune's Algorithm

The naïve half-plane intersection approach runs in $O(n^2 \log n)$. Fortune's algorithm runs in $O(n \log n)$ and is optimal (sorting reduces to Voronoi construction).

A horizontal sweep line $\ell$ moves top to bottom. Instead of tracking the intersection of $\text{Vor}(P)$ with $\ell$ (which depends on sites below $\ell$ not yet seen), the algorithm maintains the beach line:

Beach Line
The locus of points equidistant from the nearest site above $\ell$ and from $\ell$ itself. Each site above $\ell$ contributes one parabolic arc. When the sweep line is at height $\ell_y$, the parabola for site $p_j = (p_{j,x}, p_{j,y})$ is: $$y = \frac{1}{2(p_{j,y} - \ell_y)}\Bigl(x^2 - 2p_{j,x}\,x + p_{j,x}^2 + p_{j,y}^2 - \ell_y^2\Bigr)$$
Figure 7 — Beach line evolution as $\ell$ sweeps downward. Breakpoints (orange) trace Voronoi edges.
Observation 5.2
The beach line is $x$-monotone (each vertical line intersects it exactly once). Breakpoints lie on Voronoi edges and trace the diagram exactly as $\ell$ moves.

Two types of events drive the algorithm:

  • Site event — $\ell$ reaches a new site $\Rightarrow$ a new parabolic arc appears, starting a new Voronoi edge.
  • Circle event — a beach-line arc disappears $\Rightarrow$ two growing edges meet at a Voronoi vertex.
Lemma 5.1
The only way a new arc can appear on the beach line is via a site event.

Proof (by contradiction): Suppose arc $\beta_j$ appears without a site event.
Case 1: $\beta_j$ emerges from within arc $\beta_i$. At the tangency moment, both parabolas share exactly one point. Subtracting their equations gives a degree-2 polynomial in $x$ with equal leading terms — it must have 0 or 2 roots, not exactly 1. Contradiction.
Case 2: $\beta_j$ appears between arcs $\beta_i$ and $\beta_k$. At that moment a circle $C$ through $p_i, p_j, p_k$ is tangent to $\ell$. Moving $\ell$ slightly downward, one of $p_i$ or $p_k$ enters $C$ — the circle is no longer empty. Contradiction. $\square$
Lemma 5.2
The only way an arc can disappear from the beach line is via a circle event.

Proof: Suppose arc $\alpha'$ for $p_j$ (between arcs of $p_i$ and $p_k$) vanishes. At that moment, the three parabolas share a common point $q$ — a circle through $p_i, p_j, p_k$ with center $q$ is tangent to $\ell$. No site lies inside this circle (otherwise $q$ would not remain on the beach line), so $q$ is a true Voronoi vertex. $\square$

5.4–5.6 — Data Structures and Complexity Summary

Observation 5.3
The number of arcs on the beach line is always $\leq 2n - 1$.

The algorithm uses three data structures:

  • Diagram under construction — Doubly-Connected Edge List (DCEL) with a large bounding box added at the end.
  • Beach line — balanced BST $T$. Leaves store arcs (each holding a site); internal nodes store breakpoints $\langle p_i, p_j \rangle$.
  • Event queue — priority queue ordered by $y$-coordinate (highest first). Holds site events (at site $y$) and circle events (at lowest point of empty circle).
QuantityBound
Number of eventsO(n)
Per-event processingO(log n)
Total timeO(n log n)
OptimalityOptimal — sorting reduces to Voronoi

§6 Conclusion

Computational geometry shows that geometric problems — despite their intuitive, often visual nature — harbor deep and intricate structure. Solving them correctly and efficiently demands a careful bridge between mathematics and algorithm design.

From convex hull to Voronoi diagrams and segment intersections, each problem is built from three core components: understanding the geometric behavior of objects, analyzing the mathematical structure of the problem, and choosing data structures that model this behavior at minimum time and space cost. This synthesis — converting continuous geometric relations into discrete, provable, efficient algorithms — is the power of computational geometry.

The analysis of algorithms reveals that even the smallest geometric insight, such as the distinction between a left and right turn or the definition of a perpendicular bisector, can lead to algorithms with dramatically different speed and numerical stability. Structures like Voronoi diagrams and Delaunay triangulations further show that computational geometry is not merely local — it enables the reconstruction of global, topological, and network-level relationships.

The field's importance grows clearer in real applications: map analysis, spatial data modeling, machine learning (nearest-neighbor methods), robotics, computer vision, and GIS all rely on algorithms that process geometry quickly, correctly, and stably. Computational geometry exists precisely to meet that need — not as a mere collection of algorithms, but as a framework for converting geometric intuition into trustworthy computation.
